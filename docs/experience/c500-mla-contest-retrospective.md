# C500 MLA decode 比赛复盘

整理日期为 2026-11-20。这里记录沐曦 C500 上的 MLA decode 比赛经验，以及哪些工作值得延续到 TileLang 的 C500 示例。

## 比赛结果与实测证据

比赛版 A275 在 OJ 的六项测试中全部 Accepted，得分 97.33。按 KV 长度 2K、4K、8K、16K、32K、64K 排列，评测器报告的耗时为 19、24、35、52、116、109 µs。与上一提交 A273 相比，8K 显示从 39 降到 35 µs，得分持平。这个对比来自两次提交。

更适合判断 8K 收益的是同机配对实验。固定 batch 1、16 个 query heads、1 个 KV head、D=512、PE=64、FP16，A273 到 A275 的完整调用在六批 AB/BA 中均更快。

| 8K 计时口径 | A273 | A275 | 耗时下降 |
|---|---:|---:|---:|
| GPU event 均值 | 41.712 µs | 38.264 µs | 8.27% |
| Host wall 均值 | 43.020 µs | 39.754 µs | 7.59% |

计时覆盖主核、归并、调用内工作区及正常同步。两版在这组测试中各通过 120 个全张量对拍。实验使用 C500 的 25% 算力切片及固定软件栈。该收益属于 A275 的 8K 实现组合，单项贡献和发布版收益需要重新测量。

## 复盘后保留的做法

1. **一起考虑 score、KV 数据和归并。** 拼接内容项与位置项进行 score GEMM，让片上的 KV tile 继续服务 PV，并把 split 间归并组织成向量化读取和多条累加链。发布版可以沿用这套思路。固定 split 数做消融，才能区分额外并行度和计算、归并方式本身的收益。
2. **完整调用决定是否保留优化。** 2K 的标量转换和位打包改法少了 401 条静态指令，120 对完整输出与对照逐位相同，但 GPU event 均值从 20.481 升到 20.750 µs，慢 1.32%，因此撤回。生成代码适合验证假设，最终取舍看同一计时边界下的配对数据。
3. **根据时间线定位开销。** A275 的分段采样中，2K 和 8K 的归并中位数都是 4.864 µs，增加的时间主要落在主核。采样的 128 次调用中，归并的 launch API 都在主核结束前返回。主核与归并之间的空档仍需要证据才能归因，不能直接当成可省掉的 Python 开销。
4. **把数值语义作为发布条件。** 16K／64K 的历史裁剪分别省略了部分 KV token。两条裁剪路线随后在各自的 100 个独立标准正态 CPU 对照用例中，全部未通过 `rtol=atol=0.002` 的全张量检查。固定指数平移和 FP16 未归一化中间值也有范围限制。发布候选从动态 max、全 token 和 FP32 split 状态起步，先补后置峰值、大幅度输入和长分块的正确性检查，再逐项评估低精度存储。

## 如何延续到上游贡献

拟在 `examples/deepseek_mla/maca/` 提交独立的 C500 MLA decode kernel、对拍和 benchmark 入口、支持范围与复现说明，目录结构参考 [AMD MLA 示例](https://github.com/tile-ai/tilelang/tree/main/examples/deepseek_mla/amd)。首个对照用 C500 的 8K 固定工况，比较发布候选与现有 MACA 实现的默认配置和合理 Split-KV 配置。通过后扩到 2K／4K，再按支持范围决定是否加更宽的 head 配置。PR 的性能表采用此次同卡、同输入、同软件栈的结果。

比赛阶段的原始证据保存在项目本地，其中 A275 的配对实测和 OJ 提交 159816 对应正向结果，A284 对应指令精简的负向结果，A280 对应时间线，A227／A230 对应裁剪的数值反证。这里保留结论和边界，供后续写代码、测试和 PR 说明时参考。

## 2026-11-23 开源整理进展

上文的逐长度恢复计划是比赛结束后的历史阶段。现在已完成参数化 C500 MLA 示例及两套软件栈的独立实卡验收，各自保留代码、README、原始计时和图：

- [旧栈验证版（6e71b2a）](https://github.com/Zhaohui-Xu/tilelang/tree/6e71b2aa09825ba1f9fbfe50823f9d7ae978a49e/examples/deepseek_mla/maca)：使用 TileLang-MetaX f549117c。
- [Dev 适配版（f1f283ab）](https://github.com/Zhaohui-Xu/tilelang/tree/f1f283ababe3d26f17f5f9855827a1f5961cdfd7/examples/deepseek_mla/maca)：使用 TileLang-MetaX dev90d49f35，补齐 MACA 方言接口和自动化正确性测试。

两版均有 22 个形状的三方完整调用比较。Dev 版对照沿用旧栈筛选后保存的配置，未在新编译器上重新调优；绝对延迟比旧栈上升，原因尚未确定。跨软件栈的相对加速比不能直接作为算法改进量。当前拟向 TileLang-MetaX 的 dev 分支贡献，维护者尚未审阅。
