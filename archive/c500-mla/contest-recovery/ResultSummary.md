## 决策

1. 冻结 A275 用于六条历史路径溯源；短序列的真实完整调用性能已经在当前卡上复现。4K 的 Cython/显式工作区及原调用方式随源码保留。性能对照包括调用和分配成本，不能归给某个单独的设备优化。
2. 原 16K 每个 split 只读 6/8 个 tile，64K 只读 15/32 个（分别读 12,288/16,384 和 30,720/65,536 个 token）。在当前标准正态输入上二者均为 0/100。完整 token 组合采用实际已在比赛期间验证的长序列工厂，同时保留 32K 的分组处理优化。
3. 完整 token 与数值稳定性分别验收。固定指数偏移 -8 及 FP16 部分量有范围限制；末尾峰值构造中最大缩放后自然对数分数约 85.33，转为 FP16 概率前使用固定偏移会溢出。记录的非有限输出不能作为通用 MLA 正确结果。当前 dense 对照各长度均通过三类检查。后续若需要把竞赛级延迟和稳定性同时带到 PR，应以此处同卡延迟为目标，并保持两类压力检查。

每项任务子目录包含 manifest、完整命令、源码哈希、stdout/stderr、起止时间、生成 host/device 源码及退出码。所有性能结果均为未插桩完整调用。本轮没有向 OJ 或 GitHub 提交。[原始结果汇总](summary.json) · [核验脚本](summarize.py) · [早期回放脚本快照](replay-a275-v1.py) · [含完整 token 入口的回放脚本](replay.py)。

对九次任务分别回收竞赛来源实现和 dense 对照的 device 源码，共十八份；静态扫描未出现主机/设备拷贝调用或外部 BLAS/mcTlass 计算调用。八项规则与设备代码审计仍沿用比赛工作区记录。
