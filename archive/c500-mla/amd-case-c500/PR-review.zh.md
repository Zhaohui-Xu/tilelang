# C500 dense MLA 提交前审查与性能报告

**结论：现有归档足够支撑一份 C500 dense MLA 示例 PR。** 同一份源码的默认调度，在 50% 算力、32000 MiB 的 C500 切片上，22 个实测形状全部降低了相对调优 TileLang-MetaX dense 示例的完整调用 wall 中位数。小 batch 的 12 个点为 1.43–2.79×；与 AMD 示例标称维度相同的 10 个大 batch 点为 1.80–2.88×。所有 132 组 wall 配对领先，event 配对为 126/132。[原始逐批记录](defaults.json)

## 贡献是什么

同一 CTA 中，更多查询头可共享一次 KV tile 读取。并行工作量少时，窄头块与沿 KV 拆分能提供足够的独立 block。工作量增加后，更宽的头块使用寄存器 fragment 保存 Q，使同一块 KV 服务更多查询头。拆分过多会增加 FP32 中间输出及归并开销。B64/H128/1K 上，在同一次配对中，16 头块为 1248 µs，宽头块为 648 µs。这个对照衡量整套宽块调度的收益。它不能单独量化 KV 复用这一项机制。[宽块配对原始数据](wide.json)

## 两类性能图

小 batch 图展示默认实现相对同卡 tuned dense 的完整调用加速，只标已测组合。B1/H16/8K 的 wall 从 92.24 µs 降至 45.10 µs。B1/H16/64K 从 563.88 µs 降至 201.91 µs。[小 batch 图（PDF）](flashmla-maca-small.pdf)

大 batch 图按 B64、B128 分栏，覆盖 H128、KV 1K/2K/4K/8K/16K。计算量沿用 AMD TileLang 脚本的 QK 与 PV 乘加计数，用六批 wall 中位数换算有效 TFLOP/s。例如 B128/H128/16K 的公开 dense、我们的默认实现、原生分页接口分别为 33.64、11.67、8.50 ms。三个系列都在同一 C500 上测得。原生分页输入已打包，页表和调度元数据已准备，调用还返回 LSE。[大 batch 图（PDF）](flashmla-maca.pdf)

## 审查发现与处理

- **性能口径可复核。** 逐行从原始样本重算并核对了 README 中 22 行的 wall 延迟、加速比及十个分页结果。小 batch 每轮 200 次预热、2000 次计时，大 batch 为 5/30，均为六轮。汇报的是热态完整调用，包含输出分配、workspace 和 kernel launch。[运行命令与环境](manifest.json)
- **AMD 对齐限于标称形状与计算量。** AMD 的 AITER driver 使用 BF16 及同批不同长度，本次 C500 为同批等长、连续 FP16。图中没有跨卡加速比。厂商原生分页调用在全部十个大 batch 点更快，已保留在主图中。
- **复现有后端前提。** 主仓将 MACA 列为生态后端；该示例在 TileLang-MetaX f549117c 和 PyTorch 2.8.0+metax3.7.1.3 执行。公开 CLI 按基线分别配对，归档的大 batch 表采用三方交错顺序。完整的原表复现使用归档驱动。[复现说明](Replay.md)
- **输入布局是调用契约。** 曾观察到非连续 KV 在固定 MACA 调用栈中退出 139。README 要求设备转换后调用 contiguous，benchmark 显式核查输入布局。原矩阵 198 次对拍及追加集合 78 次对拍均通过，两组形状有重合。[布局诊断](ABI.md)
- **通用性声明有实测边界。** 本次材料支持连续 FP16、单 token、KVH1、D512/PE64 的已测工作负载。默认调度按 head 组和 tile 数选择。公开 tuner 在 B9/H128/4K 的一次复筛选 16 splits，默认是 4。卡时结束前拟补的 held-out 三组及 N+1 没有形成完整新性能数据，均排除在图表外。[完整技术记录](ResultSummary.md)

本轮为离线源码与证据审查，复用了已归档的设备实验；绘图不改 kernel 或 benchmark。图和表可随示例提交，上游维护者仍需确认生态后端示例的目录落点。
